Mumblew — Kokoro Benchmark (second device)

Standalone, isolated test — doesn't touch the main app. Goal: find out whether this specific device can run Kokoro (local TTS) fast enough to be worth building, before committing any code to the main app. The model downloads fresh from the Kokoro CDN on first load (~80-170MB), so this needs a real internet connection.

Step 2 — Load the model

Picks WebGPU/fp32 if Step 1 found WebGPU support, otherwise falls back to WASM/q8 — the two combinations the first laptop's benchmark already validated as usable (fp16 was glitchy, q4 was slower and degraded on that GPU backend, so neither is worth re-testing here).

Step 3 — Synthesis speed test

Synthesizes three sentences of increasing length, alone (no concurrent load), and measures wall-clock synth time per sentence.

Step 4 — Concurrent load test (webcam required)

Mirrors real usage: starts your webcam and runs the same MediaPipe face-tracking model the main app uses, measures its frame rate alone for a few seconds, then again while Kokoro is synthesizing, so we can see how much they slow each other down on this specific hardware.

Step 5 — Breakeven check

Enter your real calibrated pace from the app's debug panel (shows as something like "custom (1.20x rate, 210ms/syllable)" — combine with the base-word-ms value the same panel shows, or estimate ~1.5 syllables/word if you only have the syllable number). If you don't have it handy, your last known value (650ms/word) works as a placeholder.
