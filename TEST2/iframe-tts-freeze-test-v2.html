Mumblew — iframe TTS-freeze isolation test (max stress, round 2)

The first version of this test (clean sequential calls, then interrupted- but-orderly calls at a fixed 900ms) never reproduced a freeze in 30 calls, unlike the real app's observed #10/#14/#17/#22 (Entry 24/33). This version stacks every stressor available without touching the real app: real MediaPipe camera inference running unthrottled in the background, optional synthetic CPU load, randomized/faster interrupt timing, and an overlapping "flutter" dispatch mode that fires the next speak() on a fixed clock without waiting for the previous call's cancel()/onerror/onend to resolve first — the closest isolated analogue to Entry 16's original "speak() called before the prior utterance settled" freeze mechanism.

Run in Chrome. Reload the page between the control and iframe tests — if the leak lives at the browser-process level rather than per-frame, running both in one page load would let the control test's calls poison the iframe test's result too.
